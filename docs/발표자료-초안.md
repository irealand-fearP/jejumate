## 슬라이드 2 — 문제 정의 & 타깃  (▶ 문제 정의·기획)

**누구를 위해, 어떤 문제를 푸는가**

- **타깃**: 제주에 온 런케이션 청년 · 대학생 (지역·인맥·최신 정보가 없는 상태)
- **문제**: 정보는 넘치는데 *믿을 수 있는* 정보가 없다
  - 블로그·광고·오래된 글이 뒤섞여 "지금 진짜 학생들이 쓰는 정보"를 가리기 어렵다
  - 카톡 오픈채팅에는 살아있는 정보가 있지만 → 스크롤 지옥 + 광고/소음 + 개인정보 노출
- **핵심 질문**: "제주공항 택시팟 지금 있나요?" 처럼, *커뮤니티 실사용* 답이 필요한 순간

**말하기 포인트**
> "출처 불명의 주장이 '소음'처럼 쌓여 무엇을 믿을지 판단하기 어려운 시대에,
> 우리는 '많은 정보'가 아니라 '검증된 정보'를 주는 서비스를 만들었습니다."

## 슬라이드 5 — 모델 설계: RAG 파이프라인  (▶ 모델 설계·활용)

**gpt-5-mini 를 "근거 안에서만" 말하게 하는 구조**

```
질문
 └─▶ 임베딩(text-embedding-3-small)
      └─▶ pgvector 최근접 3건 검색 (ivfflat 인덱스)
           └─▶ 유사도 threshold 0.5 컷
                ├─ 통과: gpt-5-mini 1회 호출
                │        → (1) 근거만으로 답 생성
                │        → (2) 각 근거가 답을 뒷받침하는지 자가 검증(citations)
                │        → answer_source = "community"
                └─ 미달: gpt-5-mini 일반 지식 답변
                         → answer_source = "general_knowledge" (배지로 구분)
```

**설계 근거(왜 이렇게 했나)**
- 검색을 DB 안(pgvector)에서 → 문서가 2천 건 늘어도 응답이 문서 수와 무관하게 빠름
- threshold 컷으로 **"아무 문서나 갖다 붙이는" 폴백 제거** → 근거 없으면 없다고 인정
- LLM 호출 **1회**로 답변+검증 동시 처리 → 비용 절약(팀 예산 80달러 제약 반영)

## 슬라이드 6 — 성능을 끌어올린 방법들  (▶ 모델 설계·활용)

**모델은 고정, 방법으로 승부**

| 시도 | 문제 | 조치 | 결과 |
|------|------|------|------|
| 프롬프트 튜닝 | 근거가 확실한데도 "답변 어렵다"며 회피 | "요약·패턴 설명은 추측이 아님"을 명시, 회피 조건을 좁힘 | 근거 있으면 자신 있게 답, 무관할 때만 회피 |
| 근거 없음 처리 | 정적 회피 문구는 사용자 경험 나쁨 | 일반 지식 폴백 + "커뮤니티 근거 없음" 배지 | 항상 답은 주되 출처는 구분 |
| 검색 속도 | 전체 문서 파이썬 계산으로 6초+ | pgvector 최근접 3건 | 검색 수백 ms |
| 비용 관리 | 예산 제약 | `reasoning_effort=minimal`, `max_completion_tokens=700`, 단일 호출 | 품질 유지하며 토큰 절감 |

**말하기 포인트**
> "각 선택마다 '왜'가 있습니다. 특히 프롬프트 버그는 실제로 겪고 고친 것이라,
> before/after를 데모로 보여드릴 수 있습니다."

## 슬라이드 7 — 신뢰성 증명: 근거 대조 & 신뢰도 등급  (▶ 신뢰성·설득력)

**답을 '검증'까지 하는 게 핵심**

- gpt-5-mini 가 답을 만든 뒤, **각 근거가 그 답을 실제로 뒷받침하는지 스스로 표시**
- 뒷받침 비율로 **신뢰도 등급** 산출:

| 등급 | 의미 |
|------|------|
| high | 근거 전부가 답을 뒷받침 |
| medium | 일부만 뒷받침 |
| **low** | 근거는 있었지만 하나도 뒷받침 못함 → **환각 의심 신호** |
| none | 근거 0건(일반 지식 답변) |

- 화면 노출: `검증된 출처 N / 전체 M`, 출처별 `supports` 표시, community/general 배지
- 원본 대조: 각 출처 카드가 실제 카톡 원문(rag_sources)으로 연결

**말하기 포인트**
> "일반 챗봇은 틀려도 그럴듯하게 말합니다. 저희는 'low(근거 불일치)'를
> 스스로 드러내서, 사용자가 언제 조심해야 하는지 알 수 있게 만들었습니다."

## 슬라이드 9 — 서비스 견고성: 배포 & 속도  (▶ 서비스 견고성)

**"죽지 않고 빠르게" 를 실제로 배포로 증명**

- **이중 배포**: Vercel(백업) + **자체 서버(systemd 상시 프로세스, 메인)**
- **응답 속도**:
  - 일반 API: 자체 서버 **0.06~0.1초** vs Vercel 1.2~1.8초 → **15~20배**
  - RAG 질문: pgvector 도입으로 **9~18초 → 2.4~4.4초**
- **운영 안정성**:
  - 파티 수명주기 자동 정리(만료 숨김 → 실삭제), Postgres 커넥션 재사용
  - 실제 브라우저 클릭 QA로 등록→신청→승인→채팅 전 흐름 검증
- **사용자 친화**: 모바일 웹앱, 근거 배지·지도, 답변에 안전 안내 문구 상시 노출

**말하기 포인트**
> "콜드스타트 지연이라는 구조적 한계를 만나서, 상시 프로세스 자체 서버로
> 옮겨 15~20배 빠르게 만든 게 이번 프로젝트에서 가장 실전다운 결정이었습니다."

## 슬라이드 10 — 보안 & 개인정보 보호  (▶ 보안)

**민감 정보를 다루는 세 겹의 방어**

1. **비밀 키 관리**
   - `OPENAI_API_KEY`·`DATABASE_URL` 은 서버 `.env`에만, `.gitignore`로 커밋 차단
   - 카카오맵 키·수집 시크릿도 환경변수/Secrets, **코드에 하드코딩 금지**
   - 수집·크론 엔드포인트는 `INGEST_SECRET`/`CRON_SECRET` 인증 + **키 회전** 이력
2. **사용자·원본 데이터 보호**
   - 적재 전 개인정보 마스킹(전화·SNS·URL)
   - 익명 ID 기반, 프로필/유저 데이터는 삭제 로직에서도 영구 보존 분리
3. **모델 사용 안전장치**
   - Codex 실행 샌드박스 `network_access=false`, 파괴적 명령 승인제

**말하기 포인트**
> "API 키가 GitHub에 올라가는 사고가 가장 흔한데, 저희는 예제 파일엔 빈 값만,
> 실제 값은 서버 환경변수에만 두는 원칙을 처음부터 지켰습니다."

## 부록 A — 예상 질문 대비 (QnA 10분)

- **Q. gpt-5-mini 로 어떻게 신뢰도를 판단하나? 그것도 환각 아닌가?**
  A. 판단을 *숨기지 않고 등급으로 노출*하는 게 핵심. low(근거 불일치)를 사용자에게 보여 자기교정 여지를 준다. 미래엔 사람 피드백으로 캘리브레이션.
- **Q. threshold 0.5 근거는?**
  A. 기존 검색 파이프라인 기준 이식 + 실사용 질문으로 관찰. [실측 근거 보강]
