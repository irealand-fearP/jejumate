# RAG 개선 여정 — 발표용 스토리 (2026-07-15 정리)

> "아무 문서나 갖다 붙이던 챗봇"에서 "근거로 답하는 시스템"까지.

## 0단계 · 출발점: 사실상 가짜 RAG (7/7)
초기 버전은 키워드 LIKE 검색 + "매칭 없으면 아무 문서나 반환". 무관한 질문에도 엉뚱한 문서를 근거인 척 붙임.
→ 문제 정의: "그럴듯한 답"이 아니라 "근거 있는 답".

## 1단계 · 진짜 검색으로 교체 (7/7)
OpenAI 임베딩 + 코사인 유사도 + 임계값 0.5. **근거 미달이면 임의 문서 반환 금지** 원칙 수립(현재까지 유지되는 핵심 규약).

## 2단계 · 데이터 확보 (7/8)
시드 45건 → 카카오톡 오픈채팅(계절학기방 1,164명) 실시간 수집 파이프라인(노이즈 필터·개인정보 마스킹). 근거 수천 건으로.

## 3단계 · 속도 (7/8 밤)
문서 증가로 응답 9~18초 → **pgvector**로 2.4~4.4초. 문서가 늘어도 검색이 느려지지 않는 구조.

## 4단계 · 정직함의 설계 (7/9)
- 근거가 확실한데 회피 답변하던 프롬프트 버그 수정 → 근거 있으면 자신 있게.
- 근거 없으면 일반 지식으로 답하되 **"커뮤니티 근거 없음" 배지**(`answer_source`)로 구분.

## 5단계 · 수집 완전 자동화 (7/13~14)
중간 서버 의존 제거, 카카오톡 PC 내보내기 자동화(10분 주기 무인). 전체 이력 백필로 근거 **5,785 → 10,600여 건**.

## 6단계 · 측정이 방향을 바꿈 (7/15) ★발표 포인트
팀원의 RAGAS 정량평가: "무관한 커뮤니티 글이 검색되면 품질 **−21.6%**" — 데이터가 문제를 특정.
→ **출처 라우팅** 도입: 공식·행정 질문은 제주대 공식 자료·통합검색·캠퍼스맵으로, 생활·동행 질문은 커뮤니티로.

## 7단계 · 재평가로 검증 (7/15)
- **Faithfulness 0.345 → 0.806 (2.3배)** — 환각 감소의 정량 증거
- 근거 활용도 0.571 → 0.875
- 관련성 점수 하락은 "지어내는 대신 정직하게 출처 안내"를 택한 의도된 트레이드오프

## 한 줄 요약
"우리는 RAG를 '붙인' 게 아니라, 측정하고 고치기를 반복해 '길러냈습니다'. 가짜 검색 제거 → 실데이터 파이프라인 → 속도 → 정직한 폴백 → 정량평가로 약점 발견 → 출처 라우팅 → 환각 2.3배 개선 검증."
