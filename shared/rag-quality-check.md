# RAG 품질 점검 (카톡 실데이터 기준)

대상: 배포판 Postgres(서울 리전) `rag_documents` 중 `source_type='kakao_chat'`,
총 **1,971건**(2026-07-08 하루 새 수집분). threshold(0.5)·pgvector 검색 로직은
건드리지 않고, 지금 쌓인 실데이터로 RAG 파이프라인이 실제로 어떻게 동작하는지
점검한 뒤, 발견된 이상 사례 중 두 가지(회피 답변 과잉·시스템 메시지 혼입·마스킹
사각지대)는 실제로 수정하고 재검증했다.

## 1. 카테고리 분포 (랜덤 샘플 200건 중 199건 분류)

전체 1,971건 중 무작위 200건을 뽑아 gpt-5-mini로 분류(이동/밥친구/러닝/기타/무관잡담
5종, 20건씩 배치 호출). 전수조사가 아니라 샘플 기반 추정치다.

| 카테고리 | 건수 | 비율 |
|---|---|---|
| 이동 | 67 | 33.7% |
| 기타 (중고·나눔·질문 등) | 67 | 33.7% |
| 무관잡담 | 38 | 19.1% |
| 밥친구 | 17 | 8.5% |
| 러닝 | 10 | 5.0% |

**시사점**: '이동(택시팟)'이 압도적 비중. '러닝'은 5%로 가장 적어 관련 질문에 대한
근거 커버리지가 얕을 수 있음. '무관잡담'이 19%로 적지 않아, 노이즈 필터를 통과한
문서 중 상당수가 실제로는 정보성이 낮다(이번에 시스템 메시지 혼입분은 별도로 수정,
아래 3-① 참고).

## 2. 데모 질문 9개 실행 결과 (관련 6 / 무관 3) — 수정 전/후 비교

실제 배포 DB에 대해 `answer_rag_question()`을 그대로 호출한 결과(임의 가공 없음).
**수정 전**에는 근거를 찾은 관련 질문 4건이 전부 회피 답변으로 끝났으나,
`rag_answer_service.py`의 답변 생성 프롬프트를 수정한 **수정 후**에는 모두 근거
기반의 실제 답변을 생성한다.

| 질문 | 구분 | sources | 수정 전 confidence / 답변 | 수정 후 confidence / 답변 |
|---|---|---|---|---|
| 함덕 해수욕장 가는 택시팟 있나요? | 관련 | 3 | low (0/3) — "답변하기 어렵습니다" | **high (3/3)** — "네, 학생들이 함덕 해수욕장에서 택시팟을 자주 구합니다. 예: '지금 함덕 해수욕장에서 긱사 가는 택시 팟 구해요!' ..." |
| 에코랜드 가는 택시 같이 탈 사람 있나요? | 관련 | 3 | low (0/3) — "답변하기 어렵습니다" | **high (3/3)** — "네 있어요. 제대에서 에코랜드 가실 분들이 택시 같이 타자고 글을 올렸습니다. 1박2일 코스(할인권 18,900원, 총 할인 63,600원)로..." |
| 흑돼지 점심 같이 먹을 사람 구해요 | 관련 | 3 | **high(3/3)인데 "답변하기 어렵습니다"(모순)** | **high (3/3)** — "네, 학생들이 '내일 흑돼지 점심뷔페 같이 가실 분'이라는 식으로 직접 모집하고 있어요..." |
| 돈물국수나 콩국수 맛집 추천해줘 | 관련 | 3 | medium (1/3) — "답변하기 어렵습니다" | medium (1/3) — "근거들에서 학생들이 추천한 식당은 '돈물국수'입니다. 오픈런해서 콩국수 먹으러 가자는 모집이 있고, 꿩메밀칼국수로도 유명..." |
| 서핑이나 패들보드 체험할 수 있는 곳 있나요? | 관련 | 0 | none — "정보를 찾지 못했어요"(threshold 미달) | 동일(변경 없음, retrieval은 안 건드림) |
| 기숙사에서 섬유유연제 좀 빌릴 수 있을까요? | 관련 | 0 | none — "정보를 찾지 못했어요"(threshold 미달) | 동일(변경 없음) |
| 제주도에서 스노보드 탈 수 있는 곳 있나요? | 무관 | 0 | none — "정보를 찾지 못했어요" | 동일(정상 — 여전히 허위 정보 생성 없음) |
| 외국인 유학생 비자 연장은 어떻게 하나요? | 무관 | 0 | none — "정보를 찾지 못했어요" | 동일 |
| 제주 4.3 사건에 대해 설명해줘 | 무관 | 0 | none — "정보를 찾지 못했어요" | 동일 |

**검증 포인트**: "에코랜드" 답변에 등장하는 "18,900원 할인권, 총 할인 63,600원"은
실제 원문 근거에 그대로 있는 숫자다(직접 대조 확인) — 프롬프트를 느슨하게 바꾼 게
아니라 "근거에 있는 내용을 자신 있게 요약"하도록 바로잡은 것이라, 근거 밖 숫자를
지어내는 부작용은 없었다. 무관 질문 3건도 여전히 전부 정상적으로 "근거 없음"
처리되어, 회피 answer를 줄인 것이 과도한 답변 생성(환각)으로 이어지지 않았음을
확인했다.

## 3. 발견된 이상 사례

### ① 카카오톡 시스템 메시지가 노이즈 필터를 통과함 — **수정 완료**
"~님이 들어왔습니다/나갔습니다", "메시지가 삭제되었습니다" 같은 카카오톡 자체
시스템 문구가 실제 대화 내용에 붙어서 그대로 RAG 근거로 저장되고 있었다.

- 전수 스캔 결과: 1,971건 중 **223건(11.3%)**에 이런 시스템 문구 혼입.
- 예시: `"지금 돌아가실분~ / 벙찐 튜브님이 들어왔습니다."`,
  `"9시쯤 탑동에서 기숙사 넘어가실 분 2명 구해요!! / 티비 보는 라이언님이 들어왔습니다."`
- **수정**: `kakao_ingest.py`에 `_strip_system_notices()`를 추가해 시스템 알림
  문구만 제거하고 실제 대화 내용은 보존한다(전체 메시지를 버리지 않음). 순수
  시스템 메시지만 있던 경우(예: "메시지가 삭제되었습니다." 단독, 17건)는 제거 후
  10자 미만이 되어 기존 노이즈 필터에 자연스럽게 걸러진다. 신규 테스트
  `tests/test_kakao_ingest.py` 9건으로 회귀 검증(실제 DB에서 나온 원본 문자열
  그대로 사용).

### ② 중복 저장 의심 — **이번엔 스킵(스키마 변경 필요 가능성, 보고만)**
완전히 동일한 본문이 여러 건 존재. `add_kakao_rag_document`는 `item_id` 기준으로만
중복을 막기 때문에, 같은 텍스트가 여러 item_id로 들어오면 그대로 다 쌓인다.

- 완전 동일 본문이 2건 이상인 그룹: **245종**.
- 상위 사례: "공지글을 반드시 확인하세요!!" 40건, "메시지가 삭제되었습니다." 17건,
  "7/8 협재/한림쪽 택시팟 구해요…" 12건 등.
- 본문 기준 dedup(예: `body`에 UNIQUE 제약 또는 사전 조회 후 skip)은 스키마·적재
  로직 변경이 필요해 이번 범위에서는 손대지 않았다. 다음 작업으로 남겨둠.

### ③ 개인정보/광고성 콘텐츠 마스킹 우회 — **수정 완료**
`mask_personal_info()`가 휴대폰(010 등)과 `http(s)://` URL만 마스킹하고 있었다.

- 전수 스캔 결과: 랜드라인(지역번호) 번호 3건(예: `064-754-2023` 제주대 교육혁신과,
  `064-745-1324` 민간 요트투어 광고), 인스타그램 핸들 1건(`@muzigae_yacht`) 미마스킹.
- **수정**: `_LANDLINE_PATTERN`(02, 031~064 등 지역번호)과
  `_INSTAGRAM_HANDLE_PATTERN`(`@닉네임`)을 추가해 각각 `[연락처 비공개]`,
  `[SNS 계정 비공개]`로 치환. 기존 휴대폰·URL 마스킹은 그대로 유지(회귀 테스트로
  확인). 광고성 콘텐츠 자체(검증 안 된 상업 프로모션이 근거로 유입되는 문제)는
  마스킹과 별개 이슈라 이번엔 손대지 않음.

### ④ RAG 답변 생성이 실제 채팅 근거에 과도하게 회피 답변함 — **수정 완료(가장 중요)**
2번 표의 "수정 전" 컬럼대로, 근거를 찾은 관련 질문 4건 모두 최종 답변이 "제공된
정보로는 답변하기 어렵습니다"였다. 벡터 검색 자체는 정확했다(예: "함덕 해수욕장
택시팟" 질문에 유사도 0.62~0.64로 정확히 일치하는 근거 3건을 찾음). 특히 "흑돼지
점심" 질문은 confidence_grade가 high(3/3 일치)로 나오는데도 답변 텍스트는 회피
응답이라는 모순까지 있었다.

**원인**: `rag_answer_service.py`의 `_SYSTEM_PROMPT`가 "근거에 없는 내용은 추측
금지"를 지시했는데, 모델이 이걸 "실제 카톡 글(OO 구해요! 같은 개별 모집 글)을
일반화·요약하는 것도 추측"이라고 과도하게 넓게 해석해 회피 답변으로 도망갔다.

**수정**: 프롬프트에 다음을 명시했다.
1. 개별 모집 글이라도 질문 주제와 실제로 일치하면 훌륭한 근거이니 자신 있게 답할 것.
2. "추측 금지"는 근거에 전혀 없는 새 사실(장소·요금·운영시간 등)을 지어내지 말라는
   뜻이지, 근거 내용을 요약·일반화하지 말라는 뜻이 아님을 명확히 함.
3. 회피 답변은 근거가 주제와 실제로 무관할 때만 쓰도록 제한.
4. 회피 답변을 선택한 경우 그 근거들은 citations에서 `supports: false`로 표시하게
   해서, "회피했는데 신뢰도 high"라는 모순 자체가 구조적으로 재발하지 않게 함.

**재검증 결과**(2번 표): 4건 모두 근거 기반의 구체적 답변으로 바뀌었고
(confidence high/high/high/medium), 무관 질문 3건은 여전히 허위 정보 없이 정상
처리됨. 근거 밖 숫자를 지어내지 않는 것도 원문 대조로 확인(에코랜드 할인 금액).

## 요약

- 카테고리 분포: 이동 33.7% ≈ 기타 33.7% > 무관잡담 19.1% > 밥친구 8.5% > 러닝 5.0%.
- **④번(회피 답변 과잉) 수정이 이번 점검의 핵심 성과** — 신뢰도 높음(high)으로
  표시되면서도 실제로는 답을 안 주는 모순이 해커톤 데모에서 "검증 기능이 쓸모
  없다"는 인상을 줄 뻔했는데, 프롬프트 수정으로 근거가 명확할 때 자신 있게 답하고
  무관할 때만 회피하도록 바로잡았다.
- ①(시스템 메시지 혼입)·③(마스킹 사각지대)도 함께 수정 완료, 회귀 테스트
  9건 추가(`tests/test_kakao_ingest.py`).
- ②(중복 저장)는 스키마 변경 가능성이 있어 이번엔 보고만 하고 넘어감 — 다음 작업 후보.
