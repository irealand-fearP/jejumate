# 제주메이트 디자인 시안 3종 비교 v2

기존 시안은 같은 화면에 색상만 바꾼 느낌이 강해서, 이번 버전은 선택 기준이 갈리도록 정보 구조부터 다시 나눴다.

## 시안1. 현장형 로컬 피드
- 목적: 여행 중 모바일에서 바로 보고 바로 신청하는 사용성.
- 핵심: 날씨, 빠른 필터, RAG 질문, 신청 가능한 피드를 한 흐름으로 배치.
- 장점: 서비스 정체성인 "혼자 가긴 아쉬울 때"가 가장 자연스럽다. 모바일 첫 화면에서 행동 유도가 좋다.
- 리스크: 발표 임팩트는 시안3보다 약하고, 운영 지표 확인은 시안2보다 느리다.
- 추천 상황: 실제 MVP 기본안.

## 시안2. 운영형 스캔 대시보드
- 목적: QA, 관리자, 발표 리허설에서 상태를 빠르게 확인.
- 핵심: 좌측 RAG/지표/필터, 우측 리스트 테이블. 정원, 읽기전용, 승인 대기를 한눈에 보이게 구성.
- 장점: 정원 초과 409, 지난글, 신청 가능 여부 같은 데모 검증 포인트가 명확하다.
- 리스크: 일반 여행자에게는 다소 업무 도구처럼 보일 수 있다.
- 추천 상황: 운영자 화면 또는 심사위원에게 기술 완성도를 보여주는 보조 화면.

## 시안3. 발표형 쇼케이스
- 목적: 해커톤 발표 첫인상과 RAG 스토리 전달.
- 핵심: 제주 이미지 히어로, 데이터 숫자, 데모 단계, 카드형 피드로 "문제-근거-행동"을 압축.
- 장점: 짧은 발표에서 가장 기억에 남는다. 카톡 시드와 RAG 근거, 정원 초과 방어를 설명하기 쉽다.
- 리스크: 실제 장시간 사용 화면으로는 이미지 영역이 커서 피드 밀도가 낮다.
- 추천 상황: 발표 오프닝 또는 랜딩/데모 모드.

## 내 선택

MVP 본 화면은 **시안1**을 추천한다. 사용자 행동이 가장 빠르고, 카톡 수집 데이터와 직접 등록 글이 한 피드 안에서 자연스럽게 섞인다.

발표 자료나 데모 첫 화면이 따로 필요하면 **시안3**을 앞에 두고, 실제 사용 화면으로 **시안1**을 보여주는 구성이 좋다. **시안2**는 운영자/QA 화면으로 분리하면 강점이 살아난다.
